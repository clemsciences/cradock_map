# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Flutter app (web-first, also Android/iOS/desktop) for the Société Archéologique de Touraine (SAT): "Le voyage de Mme Cradock en Touraine" — an interactive historical map of Mme Cradock's 1785 journey (Langeais → Cinq-Mars → Tours) plus editorial "focus" articles. All user-facing text is in French; the project is intended to eventually support French and English.

## Commands

- Install deps: `flutter pub get`
- Run (web): `flutter run -d chrome` — other platforms: `flutter run`
- Lint: `flutter analyze`
- All tests: `flutter test`
- Single test: `flutter test test/sequence_animation_test.dart` (add `--plain-name "<test name>"` to target one case)
- Production web build (as in CI): `flutter build web --base-href "/cradock_map/"`
- Static HTML pages (after the build, as in CI): `flutter test tool/generate_static_pages.dart` — writes one `<route>.html` per article/author/main page (title, description, Open Graph, JSON-LD, full text for search engines and screen readers), `404.html`, `sitemap.xml`, `robots.txt` into `build/web` (see `tool/static_pages.dart`; it runs through `flutter test` because the data imports Flutter). New routes with content must be added there too.
- Regenerate splash screens after changing `flutter_native_splash` config in `pubspec.yaml`: `dart run flutter_native_splash:create` — then check that `web/index.html` still has the `#app-loader` block (spinner + startup status under the logo, driven by the custom `web/flutter_bootstrap.js`, removed on the `flutter-first-frame` event).

CI (`.github/workflows`) runs the tests, builds web with Flutter 3.35.5 and generates the static pages on every push to `main` and deploys `build/web` to GitHub Pages under `/cradock_map/` — the base href must stay in sync with that path.

## Architecture

- **Entry / routing**: `lib/main.dart` enables `usePathUrlStrategy()` on web and mounts `MaterialApp.router` inside `MultiNotifier`. `lib/routes/routes.dart` holds `AppRoutes` (route constants + helpers) and the `go_router` config. Focus and author routes are **generated statically** by iterating over `focusData` and `authors` — there is no dynamic `:id` lookup, so adding a data entry is what creates its page. Unknown routes fall back to `WelcomeView`.
- **State**: a single `AppStateNotifier` (`lib/notifiers/app_state_notifier.dart`) provided via `MultiNotifier`. It owns map layer toggles (overlay image/opacity, track, all markers, post houses, carriage marker), `ViewMode` (balade/sequence), the selected step, and the sequence playback animation (Timer-driven play/pause/stop cycling through `StepData.steps`). Step selection is also pushed on `pathStepStream`, which `TouraineMap` listens to in order to move the camera.
- **Map** (`lib/ui/map/map.dart`): `flutter_map` with IGN "carte d'état-major" WMTS tiles (`TileProviderData`), an optional Cassini image overlay (`assets/images/extrait.jpg`, corner coordinates documented in README.md), a polyline from `PathData.points`, and markers. The map is wrapped in a `RepaintBoundary` keyed by `AppStateNotifier.mapKey` so it can be captured for printing/exporting. Tapping the map appends to `trackPoints` (a dev aid for tracing the route).
- **Content is code**: everything in `lib/data/` is hand-written Dart data. Steps (`step_data.dart`), the route polyline (`path_data.dart`), post houses, authors, and focus articles (`lib/data/focus/N_*.dart`). A focus article is a `FocusItem` composed of `FocusItemPart` factories (`paragraphWithLeftImage`, `gallery`, `citation`, `summary`, `navigation`, …) rendered by `FocusItemView`.
  - Current commune boundaries (`assets/data/communes.geojson`, IGN ADMIN EXPRESS COG, full precision) are generated by `python3 tool/fetch_communes.py` (Géoplateforme WFS); bump `EDITION` there for a new COG year and `CommuneBoundaryData.attribution` accordingly. `test/commune_boundaries_test.dart` checks that the whole itinerary is covered.
  - Images are displayed through light previews (`assets/previews/`, max 1200 px) whose size is known in advance (`lib/data/image_previews.dart`, generated), so pages lay out instantly; originals are only used for full-screen zoom and download. After adding images or a focus folder, run `python3 tool/make_previews.py` (needs Pillow; it also updates `pubspec.yaml`). `test/image_previews_test.dart` fails if an image has no preview.
  - Mme Cradock's journal (pages 281-294 of the 1896 edition, checked against the scans in `assets/texts/`) is in `lib/data/cradock_text_data.dart`, split into passages linked to step ids (`CradockTextData.passagesOf`). Articles quote it with `FocusItemPart.journal(...)`; other sources (e.g. `SoreauTextData`, a 1784 account of the same places) with `FocusItemPart.quote(text, source: ...)`. The articles follow the slides of the "Goûter de nos trésors" presentation (May 2025); their images come from it, one folder per article.
  - The references page (`lib/data/reference_data.dart`) lists every external work, archive, image holder and data set cited in the articles and the map, with links to the articles citing them (the journal and Soreau ones are derived from the quote sources). When an article cites a new work or institution, add it there; `test/references_test.dart` checks every article is cited.
  - To publish a new focus article it must be added to the `focusData` list in `lib/data/focus.dart`, **and** its asset folder (`assets/focus/N-…/`) must be listed under `flutter.assets` in `pubspec.yaml` (then run `tool/make_previews.py`), otherwise images won't load.
- **Platform splits** use conditional imports on `dart.library.js_interop`: e.g. `lib/ui/buttons/print_map_button/print_map_button.dart` (desktop vs web implementation) and `lib/managers/image_downloader.dart` (stub vs web). Follow this pattern for any web-only API (`package:web`) so non-web builds still compile.

## Conventions (from `.junie/guidelines.md` and `analysis_options.yaml`)

- One widget per file.
- Constants go in classes as `static const` (e.g. `AppRoutes`, `SatStyle` in `lib/style/style.dart`, `TileProviderData`); `SCREAMING_CASE` constant names are allowed (`constant_identifier_names: false`).
- Use double quotes (`prefer_double_quotes` lint) and always declare return types.
- Theme lives in `lib/style/themes.dart` (`AppTheme`).
- Widget tests that depend on app state must wrap the widget in `MultiNotifier` (or `ChangeNotifierProvider<AppStateNotifier>.value(...)` to inspect the notifier).
- Keep tests generated by AI in `test/` — don't delete them.
- Accessibility (WCAG 2.2 AA): images get their legend as `semanticLabel`, clickable text uses `TextLink` (keyboard + link semantics), titles are `Semantics(header: true)`, colours keep a 4.5:1 contrast (`test/accessibility_test.dart`); semantics are enabled at startup on the web (`main.dart`). The legal notice is `lib/data/legal_data.dart`.
